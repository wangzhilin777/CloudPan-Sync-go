# 二期待办（Phase 2 TODO）

## 目标

- 二期不再扩张功能面，优先把一期已经接通的主链路做实、做稳、做成可复用经验。
- 只保留三条主线：
  - 真实样本矩阵补齐
  - 执行模型与后台补传继续收口
  - 风控模板按真实样本校准

## 主线一：真实样本矩阵补齐

### 目标

- 每个协议族至少沉淀 1 条稳定、可复现、可回看证据的真实成功样本。
- 每家 provider 至少补齐 1 组基础成功样本和 1 组异常样本。

### 里程碑

1. 为每个协议族补齐至少 1 条真实上传成功样本。
2. 为每家 provider 补齐最小异常样本：
   - 授权失效
   - 限流或风控
   - 本地文件缺失
   - 覆盖降级或 pending_manual
3. 为大文件、多层目录、重试恢复补齐代表性样本。
4. 把样本沉淀到固定记录模板中，便于后续回归复用。

### 验收标准

- 状态矩阵里所有协议族都不再只有 `pending`。
- 每个协议族都能拿出至少 1 条真实成功证据。
- 关键异常场景都有可复现记录，而不是只停留在口头经验。

## 主线二：执行模型与后台补传继续收口

### 目标

- 把现在已经能用的 `leaf_first_lazy`、待补传树、重试队列、后台自动恢复继续做成稳定主能力。
- 减少“能跑，但复杂场景还要人工频繁介入”的情况。

### 里程碑

1. 继续收口后台补传候选池的调度策略：
   - 冷却
   - 时间窗
   - mode 预算
   - provider 预算
   - profile 预算
2. 补齐更细粒度的 upload checkpoint / 续传恢复链路。
3. 把大文件失败后的恢复路径做成更稳定的默认能力。
4. 继续增强暂停、恢复、重试、子树级补传之间的协同体验。

### 验收标准

- 大文件或长链路失败后，能更稳定地从已有检查点继续，而不是经常整任务重来。
- 状态页能更清楚地区分“可立即恢复”“等冷却”“等时间窗”“必须人工处理”。
- 后台补传在多 provider / 多账号场景下不会明显偏向某一类任务长期独占。

## 主线三：风控模板按真实样本校准

### 目标

- 让 `safe / balanced / fast / custom` 不只是抽象档位，而是逐渐变成有真实依据的默认模板。
- 把 provider 级、账号级的经验沉淀成默认建议，而不是每次手调。

### 里程碑

1. 根据真实联调样本回收各 provider 的默认节流建议。
2. 按协议族整理推荐的：
   - request interval
   - directory interval
   - retry limit
   - auto retry window
   - risk keywords
3. 为高风险 provider 补账号级预算建议。
4. 把样本结论同步回控制台推荐语义和默认模板。

### 验收标准

- 新建任务时，默认推荐档位更贴近真实 provider 行为。
- 同一类 provider 不再需要每次手工重新试错一轮参数。
- 风控命中后的恢复建议和默认模板能形成闭环。

## 建议顺序

1. 先补真实样本矩阵。
2. 再补执行模型与后台补传。
3. 最后集中校准风控模板。

## 不建议在二期优先做的事

- 不优先扩 provider 数量。
- 不优先重做整套 UI 视觉。
- 不优先上分布式 worker。
- 不优先做复杂导出系统。

## 一句话范围

- 二期重点不是“再做更多功能”，而是把现在这套多网盘互传内核真正打磨到更稳、更准、更省人工。
