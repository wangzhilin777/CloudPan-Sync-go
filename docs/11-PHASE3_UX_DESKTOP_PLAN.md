# 三期计划：体验收口与桌面客户端（Phase 3 UX / Desktop Plan）

## 目标

- 把当前“能用的 Web 服务”继续收口成“小白可上手的软件体验”。
- 授权、目录选择、任务创建、运行提示和发布包都要更直接，减少用户需要自己猜字段、猜路径、猜部署方式的情况。
- 保留现有服务端、Docker、NAS 部署能力，同时新增真正属于本项目的图形化桌面客户端。

## 当前默认决策

- 授权入口：OpenList 优先，Alist 兜底。
- 手动 Token / Cookie / Extra：保留为高级模式，不作为普通用户首选入口。
- 语言策略：完整 `zh-CN / en-US` 双语，默认中文。
- 中文界面：除 provider key、API 字段、协议名等必要技术术语外，不混用英文按钮和英文提示。
- 任务目录：任务向导必须支持“源端目录 -> 接收端目标目录”。
- 桌面端：采用 Wails / WebView 原生窗口方案。
- 桌面发布：首版规划 Windows / macOS / Linux 三平台包。

## 主线一：控制台体验收口

### 目标

- 控制台从“工程调试台”收口成“普通用户能看懂的管理面板”。
- Provider 能力、风控、恢复预算、smoke 证据等高级信息不再默认铺满页面。
- 按钮、图标、复选框、标签、圆角和间距统一，避免圆形 / 方形混用和文字竖排。

### 里程碑

1. Provider 能力卡默认压缩，只展示名称、状态、核心能力和授权入口。
2. 把能力详情、风险提示、fallback、恢复预算、smoke 证据等内容移入“详情 / 高级信息”折叠区或抽屉。
3. 统一按钮和表单控件样式，修复 toggle chip / checkbox 在窄屏或长文本下变形的问题。
4. 任务页、状态页和 Provider 页减少默认信息密度，常用操作优先，高级排障信息按需展开。
5. 移动端和窄屏布局重新走查，保证 Docker / NAS 用户在手机或平板上也能完成基础操作。

### 验收标准

- Provider 页首次打开不会默认展示大段英文能力字段。
- 普通用户可以按“授权 -> 选源目录 -> 选目标目录 -> 创建任务 -> 运行”完成主流程。
- 控件形态统一，不再出现同类按钮一部分圆形、一部分方形、一部分文字换行竖排。

## 主线二：完整双语与中文友好提示

### 目标

- 建立统一 i18n 机制，而不是继续零散替换文案。
- 中文模式下，界面、空状态、错误提示、运行提示、启动提示都尽量使用中文。
- 英文模式保留，方便后续对外发布。

### 里程碑

1. 为 `web/static/index.html` 和 `web/static/app.js` 建立统一翻译字典和语言切换入口。
2. 默认语言使用 `zh-CN`，支持切换并持久化到本地存储。
3. 所有导航、按钮、表单字段、toast、错误提示、空状态、确认信息都走翻译函数。
4. Provider key、API 字段名、协议名等必要技术术语保留英文，但旁边提供中文说明。
5. Windows 控制台和服务端启动日志增加中文优先的启动说明。

### 验收标准

- 中文模式下常用页面不再出现 `Run / Pause / Retry / Auth Mode / Extra Keys` 这类未解释英文按钮或字段。
- 启动后能看到中文说明：访问地址、局域网访问方式、数据目录、默认密码风险、Docker / NAS 访问提示。
- 英文模式可切换，且不会影响现有 API 字段。

## 主线三：授权引导与 OpenList / Alist 接入

### 目标

- 用户不再需要一上来就理解 Token、Cookie、Extra JSON。
- 优先通过 OpenList 获取账号和目录信息；OpenList 不可用时再尝试 Alist。
- 现有手动授权能力保留，作为高级入口和兜底。

### 里程碑

1. 新增 OpenList / Alist 连接配置区，支持填写服务地址和访问令牌。
2. 创建授权档案时优先从 OpenList 拉取可用存储、账号或目录信息。
3. OpenList 不可用或能力不足时自动提示切换到 Alist。
4. OpenList / Alist 都不可用时，引导用户进入手动 Token / Cookie 高级模式。
5. 每个 Provider 增加中文授权说明，列出需要哪些字段、如何获得、哪些字段可选。
6. 授权失败时返回中文可理解原因，不只显示 provider 原始错误。

### 验收标准

- 用户可以不看源码，按页面提示完成至少一种授权档案创建。
- 手动授权表单不再作为默认第一屏，而是高级模式。
- OpenList 优先、Alist 兜底、手动模式兜底三条路径都有明确提示和失败回退。

## 主线四：源目录到目标目录的可视化选择

### 目标

- 任务向导明确支持选择源端目录和接收端目标目录。
- 同步时保留源端相对路径，并写入用户选择的目标目录下。
- 旧任务和旧 API 调用保持兼容。

### 里程碑

1. 使用现有 `/api/providers/{key}/list`、`metadata`、`create_dir` 接口实现源端目录选择器。
2. 使用同一组接口实现目标端目录选择器，并支持创建目标目录。
3. `planner.PreviewRequest` 和 `task.CreateRequest` 新增 `targetRoot` 或 `targetPath` 字段。
4. 任务 metadata、报告和任务详情保存并展示目标目录。
5. 运行时上传、目标 metadata 预检查、重试、后台补传都使用映射后的目标路径。
6. 旧任务没有目标目录时，继续按旧逻辑处理，避免破坏历史数据。

### 验收标准

- 创建任务时能选择“源端 A 目录 -> 目标端 B 目录”。
- 上传路径符合“目标目录 + 源端相对路径”。
- 重试和后台补传不会丢失目标目录配置。
- 旧 payload 不带目标目录时仍可预览和运行。

## 主线五：图形化桌面客户端

### 目标

- 除 Docker / 服务端模式外，提供普通软件样式的客户端。
- 用户双击后打开自带面板，不需要手动打开浏览器。
- 桌面包必须来自本项目，不能混入其它项目产物。

### 里程碑

1. 新增桌面入口，例如 `cmd/cloudpan-sync-desktop` 和 `internal/desktop`。
2. 桌面入口启动内置 Go 服务，自动选择可用本地端口。
3. **用 WebView 打开本项目控制台窗口。** *(v0.3.0 使用 Chrome/Edge --app 过渡方案，v0.4.0 升级为 webview/webview)*
4. 桌面端退出时自动关闭内置服务，不留后台进程。
5. 桌面端复用现有静态控制台和 API，不维护第二套业务 UI。
6. 桌面端启动、错误和退出提示走同一套双语文案。

### 验收标准

- Windows / macOS / Linux 桌面包能启动原生窗口。
- 用户无需手动访问 `127.0.0.1` 也能进入面板。
- 退出桌面应用后，本地服务进程被清理。
- 服务端包、Docker 包和桌面包互不污染。

### v0.3.0 实现状态

- ✓ 里程碑 1、2、4、5、6 已完成
- ⚠ 里程碑 3 采用 Chrome/Edge --app 过渡方案
- 原因：优先发布核心功能可用版本
- 计划：v0.4.0 升级为 webview/webview 库实现真正的原生窗口

### v0.4.0 规划

**主要目标：升级桌面客户端为 WebView 原生窗口**

技术选型：
- 使用 `webview/webview` Go 库（轻量级，支持三平台）
- 保持现有 HTTP 服务架构，WebView 加载 localhost URL
- 不需要重构现有 API 为绑定机制

工作量评估：3-5 天
- 集成 webview 库到 internal/desktop
- 替换 Chrome/Edge --app 启动逻辑
- 测试三平台构建和窗口生命周期
- 更新 GitHub Actions 构建流程（如需要额外依赖）

验收标准：
- Windows / macOS / Linux 桌面包启动原生 WebView 窗口
- 窗口标题、尺寸、图标可配置
- 窗口关闭时正确清理 HTTP 服务
- 产物大小合理（不显著增大）

## 主线六：发布流程与 README 补强

### 目标

- GitHub Release 清晰区分服务端包、桌面客户端包和 Docker 镜像归档。
- README 继续面向小白，覆盖普通电脑、Docker、NAS、局域网访问、Cloudflare Tunnel 托管访问等场景。
- 发布资产不再出现外部项目名称。

### 里程碑

1. `.github/workflows/release-package.yml` 新增桌面客户端构建矩阵。
2. 桌面包命名使用本项目名称，例如 `cloudpan-sync-go-desktop-windows-amd64.zip`。
3. Release 中文描述说明每类包适合什么用户。
4. `SHA256SUMS.txt` 覆盖服务端包、桌面包和 Docker 归档。
5. README 增加桌面客户端使用说明，并保留 Docker Compose、NAS、局域网访问说明。
6. 增加发布产物校验，禁止出现 `cloud-clipboard` 等外部项目资产名。

### 验收标准

- Release 页面为中文说明。
- 用户能根据 README 判断自己应该下载桌面包、服务端包还是 Docker 包。
- Docker 归档继续包含 `latest` 标签。
- GitHub Actions 产物不包含其它项目包。

## 测试计划

- 后端单测：覆盖目标目录映射、任务 metadata、上传路径、重试和后台补传继续沿用目标目录。
- API 测试：覆盖 OpenList 成功、OpenList 不可用转 Alist、手动授权高级模式、授权失败中文错误。
- 前端检查：执行 `node --check web/static/app.js`，并增加 i18n key 覆盖检查。
- UI smoke：覆盖 Provider 卡默认折叠、授权向导、源目录选择、目标目录选择、创建任务、任务路径展示。
- 桌面 smoke：覆盖三平台可启动窗口、自动启动服务、退出清理进程。
- 发布验证：覆盖服务端包、桌面包、Docker 包、SHA256 和资产名白名单。
- 清理要求：每次测试、构建、smoke 后清理临时进程、缓存、临时数据库和构建残留。

## 不建议在三期优先做的事

- 不优先继续扩 provider 数量。
- 不优先重写整套 provider runtime。
- 不优先做全原生 Fyne 业务界面，避免维护两套 UI。
- 不优先做复杂分布式 worker。
- 不优先把 OpenList / Alist 变成同步执行内核；它们只作为授权和目录引导入口。

## 一句话范围

- 三期重点不是“再堆更多 provider”，而是把现有多网盘互传能力做成用户能顺利授权、能选目录、看得懂、能用桌面客户端启动、能从 Release 正确下载的软件。
